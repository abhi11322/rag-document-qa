# PDF RAG Application

A Retrieval-Augmented Generation (RAG) application that answers questions about a PDF document, built as a technical assessment.

## Status

Ingestion, chunking, embedding, ChromaDB retrieval, grounded generation (Gemini), and the FastAPI layer are implemented.

## Tech Stack

- **Python**
- **FastAPI** — HTTP API (`POST /ask`, `GET /health`)
- **LangChain** — orchestration
- **ChromaDB** — vector store
- **Sentence Transformers (Hugging Face)** — embeddings
- **Google Gemini** — answer generation

## Setup

1. Create a virtual environment and install dependencies:
   ```
   python -m venv .venv
   .venv/Scripts/activate   # Windows
   pip install -r requirements.txt
   ```
2. Copy `.env.example` to `.env` and fill in `LLM_API_KEY` (see comments in that file).
3. Build the vector index from `data/Document.pdf`:
   ```
   python scripts/build_index.py
   ```
4. Start the API:
   ```
   uvicorn app.main:app --reload
   ```

## API Usage

- `GET /health` — liveness check.
- `POST /ask` — ask a question about `data/Document.pdf`.
- `GET /docs` — interactive Swagger UI (auto-generated by FastAPI).

**Example request:**
```
curl -X POST http://127.0.0.1:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question": "What are the three stages of RAG?"}'
```

**Example response:**
```json
{
  "answer": "The RAG research paradigm is categorized into three stages: Naive RAG, Advanced RAG, and Modular RAG.",
  "sources": [
    {"page_number": 1, "source": "Document.pdf"},
    {"page_number": 2, "source": "Document.pdf"},
    {"page_number": 14, "source": "Document.pdf"}
  ]
}
```

Questions that are empty/whitespace-only return HTTP 422. Questions unrelated to the document return HTTP 200 with an answer stating the information could not be found in the document, rather than a fabricated answer.
